# ezsys specification

This is the list of every behavior ezsys guarantees, each under a stable requirement ID. Every requirement has one of two levels. A **Proved** requirement holds for every input, and is backed by a quantified law (a `for` or `exs` binder) in `LAWS.bend` that passes the proof gate. A **Trusted** requirement is an assumption ezsys cannot check from inside its own gate, and it is listed in the trust boundary below. A Proved requirement whose laws have not all landed has status **pending**: we intend to prove it, and until then it is not guaranteed. The proof gate is this check: the first line `bend PROOF.bend` prints is exactly `ALL PROOFS CHECK`. Tests and fixtures are never evidence for a requirement.

The requirements are about the public interface in `main.bend`. Its pure functions are thin names for the functions in `src/text.bend`, `src/str.bend`, `src/clock.bend` and `src/errno.bend`, which `ENTRY.bend` states laws for, and every decision its IO functions make is a function in `src/step.bend` or `src/dir.bend`; those modules do no IO, so `LAWS.bend` and `PROOF.bend` import them and nothing else. `src/sys.bend` runs the effects and acts on the answers (SYS-TRUST-4). It is the only module with foreign code: one effect that flushes and renames a file (SYS-TRUST-1), one that reads the wall clock (SYS-TRUST-2) and one that reads a directory's names (SYS-TRUST-5).

Base has no rename, and the services ezsys was written for renamed with `Process.run("mv", ...)`. ezsys adds an effect instead, a C file and its JS twin, because `mv` is a second program found on `PATH` at run time, costs a fork and exec, can only report success as an exit status, cannot flush the file first, and falls back to copying and deleting when the two names are on different filesystems, which is not atomic. `rename(2)` is one system call that is atomic on one filesystem and fails with `EXDEV` across two, and the effect flushes the file with `fsync(2)` before it renames it. The clock is an effect for the same reason: Base's `IO.now()` is milliseconds since the process started, not the wall clock.

Base also has no way to list a directory, and those services ran `find` with `Process.run` for it, a second program again. `dir.list` reads the names with an effect of its own, `opendir(3)` and `readdir(3)` (`fs.readdirSync` on the JS lane), and decides in pure code which names to answer and in what order.

## Format

A requirement table is any table whose header row is exactly `| ID | Requirement | Level | Status | Law |`. An ID is uppercase segments joined by hyphens, at least two (`[A-Z][A-Z0-9]*(-[A-Z0-9]+)+`), unique within the requirement tables, and never reused once released. Level is `Proved` or `Trusted`. Status is `proved` or `pending` for a Proved row and empty for a Trusted row. A Law cell holds `<path> <law>` entries, paths relative to this file, separated by `; `. A proved row names one or more laws, and together they prove it. A pending row may name laws that each prove part of it; the row stays pending until its requirement is proved in full, and "Left to prove" says what is missing.

A law proves a requirement when a comment line `# <ID>`, alone on its line, sits in the unbroken comment block directly above its `law` line. A law may carry several tags, one per line:

```
# LAW: a template with no marker is left unchanged
# SYS-TEXT-1
law fill_unmarked:
```

A tag may name a proved or a pending requirement, never a Trusted one or an ID no requirement table lists. bolt's `trace` rule checks all of this over the whole tree, and its `closed` rule rejects a law with no binder; both are errors in `bolt.bend`.

### Wall clock (SYS-TIME)

`time.now()` answers whole seconds since 1970-01-01T00:00:00Z as a `U32`, which holds every second up to 2106-02-07T06:28:15Z, and the milliseconds past that second. `time.iso(secs, ms)` writes them as ISO 8601 UTC, `YYYY-MM-DDTHH:MM:SS.mmmZ`, with the proleptic Gregorian calendar of Howard Hinnant's `civil_from_days`; the milliseconds are written as their last three decimal places. `time.now_iso()` is `time.iso` of `time.now()` (SYS-TRUST-4). Years before 1970, 1900 among them, are outside the input, so the century rule is checked at 2100 instead.

`time.civil(secs)` answers the civil fields of an instant in UTC as `(year, month, day, hour, minute, second, weekday)`, with the date and time `time.iso` writes and the ISO 8601 weekday, 1 for Monday to 7 for Sunday (ISO 8601-1:2019 §3.2.2 and §4.3.2.2, Python's `isoweekday()`). `time.iso_week(secs)` answers the ISO 8601 week date's year and week (ISO 8601-1:2019 §3.2.2 and §5.2.4.3, Python's `date.isocalendar()`, `date`'s `%G` and `%V`): a week runs Monday to Sunday, and week 1 of a year is the week that holds its first Thursday, so a day belongs to the ISO year and week of its week's Thursday, and the ISO year of 29 to 31 December or 1 to 3 January can be the next or the previous calendar year. A year has 53 weeks when it starts on a Thursday, or is a leap year that starts on a Wednesday (2015, 2020, 2026), and 52 otherwise. `time.iso_week_text(secs)` writes them as `date -u +%G-W%V` does, `YYYY-Www` with the week in two digits, as in `2026-W43`. 1 January's day number is Howard Hinnant's `days_from_civil`. The weekday is counted from day 0, a Thursday, one day at a time: a law can follow that count for every day, where a remainder by 7 needs U32 lemmas Base does not have. It costs the checker about 0.3 ms a day, so each anchor below takes it about 5 s.

### Text templates (SYS-TEXT)

A marker is an open delimiter, a key and a close delimiter. `text.fill(template, pairs)` uses `{{` and `}}`, so `{{name}}` is the marker for the key `name`; `text.fill_with(open, close, template, pairs)` takes the delimiters, so the whole-line `<!--NAME-->` markers of a page shell are `text.fill_with("<!--", "-->", shell, pairs)`. The scan reads the template once, left to right: at an open delimiter a key starts, and it runs to the first close delimiter after it, so keys are matched exactly (spaces included) and markers do not nest. A key's value is the value of the first pair with that key, and it is written as it is, never scanned again. A key no pair has, and a marker with no close delimiter, are left as written. An empty delimiter marks nothing. The laws state these for `src/text.bend`'s `text.fill_with`, which takes the pairs as a reusable list; `main.bend` copies the caller's pairs into one in order (SYS-TEXT-6). `O` and `C` below are any nonempty open and close delimiters.

| :---- | :---- | :---- | :---- | :---- |

| SYS-TEXT-2 | For every character `h` and text `t` such that `O` does not start at `h`, filling `h` followed by `t` is `h` followed by filling `t`. | Proved | proved | LAWS.bend fill_plain |

`src/str.bend`'s text helpers are the ones Python's `str` gives a service for free, and each row names the Python behaviour it matches. They work on code points, one at a time, left to right. ### Case (SYS-CASE)

`text.lower` and `text.upper` are Python's `str.lower()` and `str.upper()` (Unicode 13's full case mappings, `SpecialCasing.txt` included) for the code points U+0000 to U+017F (ASCII, Latin-1 and Latin Extended-A) and U+0370 to U+04FF (Greek and Coptic, and Cyrillic), and leave every other code point as it is. The table in `LAWS.bend` (`lower_table`, `upper_table`) is Unicode's mapping of those code points written as runs: `Rule{lo, hi, step, to}` maps every `step`-th code point from `lo` to `hi` onto the code points from `to` in order, so `Rule{65, 90, 1, 97}` is `A` to `Z` onto `a` to `z` and `Rule{256, 302, 2, 257}` is Latin Extended-A's pairs. The special mappings to more than one code point are handled as Python does: lowercase U+0130 (`İ`) is U+0069 U+0307, and uppercase U+00DF (`ß`) is `SS`, U+0149 (`ŉ`) is U+02BC `N`, U+0390 is U+0399 U+0308 U+0301 and U+03B0 is U+03A5 U+0308 U+0301. Outside the requirement: Python writes a final sigma, U+03C2, for U+03A3 at the end of a word, which needs the cased and case-ignorable properties of every code point; `text.lower` always writes U+03C3. Python also maps code points outside the two ranges (Latin Extended-B, Latin Extended Additional, Armenian, Georgian, full-width and Deseret letters, U+1E9E, ligatures like U+FB01 and the like), which are left as they are here.

### Directories (SYS-DIR)

`dir.list(path)` answers `Result<&1, &1, U32 & String, List<&2, String>>`: the names of the entries in a directory (names only, not paths), or Base's `Fail{(errno, message)}`, a value and never an exit. The effect `ezsys.list` reads the names as the host lists them (SYS-TRUST-5), and `src/dir.bend`'s step decides the answer: it drops exactly `.` and `..` and sorts the rest ascending by Base's `String.order`, which compares code point by code point and puts a proper prefix first. That is the bytewise order of the names' UTF-8 encodings, since UTF-8 keeps code point order, so for names that are valid UTF-8 the answer is Python's `sorted(os.listdir(path))`. The laws count a name's copies with `listed` and check the order with `ascending`, both in `LAWS.bend`.

| ID | Requirement | Level | Status | Law |
| :---- | :---- | :---- | :---- | :---- |
| SYS-DIR-1 | For every list of raw names and every name, `dir.list`'s step answers the name exactly as many times as the raw names hold it when it is neither `.` nor `..`, and never when it is `.` or `..`: no name is lost, added or repeated. | Proved | proved | LAWS.bend dir_count |
| SYS-DIR-2 | For every list of raw names, every name in `dir.list`'s step's answer is no greater by `String.order` than the name after it. | Proved | proved | LAWS.bend dir_sorted |
| SYS-DIR-3 | For every answer of the directory read, `dir.list`'s step answers a failure unchanged, and the sorted names of SYS-DIR-1 and SYS-DIR-2 when the read succeeded. | Proved | proved | LAWS.bend dir_fail; LAWS.bend dir_done |
| SYS-TRUST-5 | `ezsys.list(path)` (`src/effs/dir.c`, `src/effs/dir.js`) answers `Done` of the name of every entry in the directory at `path`, each once, in the host's order, with `.` and `..` or without them, or `Fail{(errno, message)}` when the directory cannot be opened or read (a path with a NUL fails with `EILSEQ`); it never ends the process. It follows no entry, so a symbolic link is listed by its own name, and the directory is closed before the answer. A name's bytes are decoded as UTF-8 with U+FFFD for an invalid sequence, so such a name cannot be opened again from the answer; Python's `os.listdir` keeps those bytes as lone surrogates instead. | Trusted | | |

### Errors (SYS-ERR)

`err.os(code, why, path)` writes a failed file operation's `Fail{(code, why)}` the way Python's `OSError.__str__` writes an error with a file name: `[Errno N] <strerror>: <repr(path)>`, as in `[Errno 2] No such file or directory: '/tmp/x'`. The text of a code is glibc's, as Python's `os.strerror` gives it on Linux, for the codes 1 to 40 and 84 (`EILSEQ`), 95 (`EOPNOTSUPP`), 110 (`ETIMEDOUT`), 111 (`ECONNREFUSED`), 112 (`EHOSTDOWN`), 113 (`EHOSTUNREACH`), 116 (`ESTALE`), 122 (`EDQUOT`) and 125 (`ECANCELED`); `strerror` in `LAWS.bend` lists them. For any other code `why` is written as it came, where Python writes glibc's text for the code or `Unknown error N`. The path is written as Python's `repr(str)` writes it for every code point up to U+00FF: between `"` when it holds a `'` and no `"`, else between `'`; `\t`, `\n` and `\r` for those characters; `\xhh` (two lowercase hex digits) for every other code point below U+0020, from U+007F to U+00A0, and U+00AD; a backslash before a backslash and before the chosen quote; every other character as itself. Python also writes `\xhh`, `\uhhhh` or `\Uhhhhhhhh` for the code points past U+00FF that `str.isprintable` rejects (U+2028, U+200B, U+FEFF and the like); those are written as themselves here, which is outside this requirement.

| :---- | :---- | :---- | :---- | :---- |
| SYS-ERR-1 | For every code and `why`, the text of the code is the text of the first entry for it in the table `strerror`, and exactly `why` when the table has no entry for it. | Proved | proved | LAWS.bend err_table; LAWS.bend look_none; LAWS.bend look_hit; LAWS.bend look_miss |
| SYS-ERR-2 | For every code, `why` and path, `err.os(code, why, path)` is exactly `[Errno `, the code in decimal, `] `, the code's text, `: ` and the path as `repr` writes it. | Proved | proved | LAWS.bend err_os |
| SYS-ERR-3 | For every path, `repr` writes the quote, each character of the path escaped as stated above, and the quote; the quote is `"` exactly when the path holds a `'` and no `"`. | Proved | proved | LAWS.bend repr_shape; LAWS.bend quote_double; LAWS.bend quote_plain; LAWS.bend quote_both; LAWS.bend go_empty; LAWS.bend go_char; LAWS.bend esc_tab; LAWS.bend esc_newline; LAWS.bend esc_return; LAWS.bend esc_hex; LAWS.bend hex_pair; LAWS.bend esc_backslash; LAWS.bend esc_quote; LAWS.bend esc_plain |
